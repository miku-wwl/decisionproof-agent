# Offline security and execution boundary

Status: **PASS for exercised offline boundaries**, not production multi-user/cloud qualification.

The CLI binds to `127.0.0.1` only, one worker. A new empty private directory holds salted PBKDF2-SHA256 password verification (240,000 iterations), server-only AIG capability, stable binding/scope, separate decision/gate/task databases and receipts. Initialization refuses an existing nonempty directory. No plaintext password is saved or printed. Standard inherited Windows ACLs apply; Unix private directory/file modes are also set. The private path is ignored and excluded from review packages.

Login requires the trusted Origin and a custom request header. Five failed logins per minute are limited. Sessions are random opaque server-side tokens with a 15-minute monotonic expiry, HttpOnly/SameSite=Strict cookies and per-session CSRF tokens. Session tokens are not exposed to JavaScript; the CSRF value is. This uses a server-side session lookup rather than the signed-cookie design option discussed in P0. Sessions intentionally expire on process restart; decision history does not. Secure cookies are disabled only for this localhost HTTP development transport; this configuration is not a public deployment profile.

All data/Run/approval/Action APIs require authentication. All mutations validate Origin and CSRF; strict body models reject extra authority fields and separate authorization from execution bodies. Validation responses never echo credentials. Body size is bounded, trusted hosts are restricted, and CSP rejects external scripts/frames/requests. The UI uses text nodes for evidence rather than inserting untrusted HTML. The bundled AIG demo router is not mounted. AIG capability tokens never leave the server or enter prompts/receipts/browser JSON.

Actual execution uses installed `agentic-intent-gate==0.2.0` at `7261fdd2f47d2b15fabe8faac527eeee37338eb1`, without a core edit or monkeypatch. Trusted startup configures one `create_patch_review/1` binding, fixed target/revision/scope, strict flat arguments and separate policy. No timeout argument is passed: the five-second default remains. Runtime owner fencing requires explicit `--predecessor-stopped`, even for the first use of a freshly initialized directory. The operator must establish no predecessor is running; the flag does not stop one.

An acceptable immutable decision is required before any Run proposal. Authenticated Plan approval is separate from admission and independent execution authorization; a separate execute command triggers the Gateway. Exact Plan binding, version/CAS checks, durable claiming and stable effect keys come from AIG. A consumer review fingerprint confirms the shown validated Plan; it does not replace AIG's approval mechanism. Consumer denial records an event and never calls authorization. A denied decision cannot later authorize without a fresh decision.

The single executor revalidates complete identity, current decision and approved arguments. It writes one local sandbox task with effect-key uniqueness, decision uniqueness, payload digest and unique UUID receipt in its separate durable SQLite store. An independent read checks the committed row before Success. The consumer does not implement its own Action claiming/state machine. Core and task commits are distinct: a task may exist while the Action is **Unknown**. Lost acknowledgment, uncertain write or late/unverifiable result does not authorize another dispatch.

Test-only host constructor faults `fail`, `unknown` and `crash` are not HTTP options or model fields. They run only in fresh isolated test compositions. The crash test exits its own spawned child immediately after task commit; the parent verifies child termination, reopens the runtime and observes recovered Unknown with one task/attempt. It neither kills a user process nor changes core code. No external effects, patching, scanning, exploits or ticket writes exist.

Evidence: [product/security tests](../tests/test_product.py), [contract tests](../tests/test_contract_security.py), [browser result](evidence/p1a/browser-result.json). Limits: single local owner, no multi-tenant/RBAC claim, no malicious-Python isolation or guaranteed remote exactly-once effect. Actual owner's human approval is not fabricated: automated tests exercise authenticated reviewer controls using generated/test-only credentials and explicitly label that consent as scripted.
